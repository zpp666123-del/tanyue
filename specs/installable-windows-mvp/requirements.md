# 可安装 Windows MVP：需求规格

## 1. Goal

把当前通过前端门禁的 Pre-alpha 工程推进为这台 Windows 电脑上可实际安装、启动和保留数据的本地 MVP：以 SQLite 作为 Tauri 正式存储，安全导入已有 LocalStorage 数据，安装并验证 Rust/Tauri 工具链，生成安装包并完成当前用户安装。

本请求中的“都搞好”解释为完成前一轮明确剩余的 **SQLite + Tauri Windows 编译/安装/核心桌面验收**，不等于一次性完成长期路线中的全部格式适配器、签名升级和操作系统增强能力。

## 2. 用户故事

1. 作为读者，我希望关闭并重新打开桌面应用后，书籍、进度、收藏、笔记、计划和设置仍然存在。
2. 作为现有用户，我希望首次升级到 SQLite 时自动保留 LocalStorage 数据，并且迁移失败后仍能恢复。
3. 作为 Windows 用户，我希望得到一个能正常安装、启动和卸载的本地安装包。
4. 作为维护者，我希望 Rust、Tauri 和前端门禁都能在本机重复执行，以便继续开发和打包。
5. 作为正在工作的用户，我希望弹阅的悬浮入口和阅读弹窗不会无故抢走当前输入焦点。

## 3. 验收标准

### R1：本机开发工具链

- 当本机缺少 Rust 时，安装流程应通过官方可信渠道安装 stable Rust 工具链，并包含 Cargo、rustfmt 和 Windows MSVC target。
- 当 Tauri 构建所需的 MSVC Build Tools、Windows SDK 或 WebView2 缺失时，安装流程应只补齐缺失组件，不安装与本项目无关的软件。
- 安装完成后，`rustc --version`、`cargo --version` 和 `cargo fmt --check` 应可在本机成功执行。
- 所有系统级安装来源和版本应记录到 `PROJECT_STATUS.md`，不得把未完成的安装写成成功。

### R2：SQLite 正式持久化

- 当应用运行在 Tauri 中时，系统应使用应用数据目录下的 SQLite 数据库作为正式状态来源，而不是继续以 LocalStorage 为主存储。
- 数据库应至少持久化书籍、片段原文与追溯、阅读状态、收藏、笔记、活动事件、阅读计划、应用设置和当前导航状态。
- 当用户修改进度、收藏、笔记、计划或设置时，系统应在安全事务中持久化变更；写入失败应返回明确错误，不得静默伪装成功。
- 当应用运行在普通浏览器预览中时，系统应继续使用 LocalStorage 作为演示回退，保证现有预览方式可用。
- 数据库迁移应版本化、可重复执行，并通过外键、唯一序号和必要索引保护数据一致性。

### R3：LocalStorage 一次性迁移与恢复

- 当 Tauri 首次启动且 SQLite 尚无用户状态、同时检测到合法 LocalStorage 状态时，系统应先创建可恢复备份，再在单一事务中导入 SQLite。
- 当迁移成功时，书籍数量、片段数量、当前进度、确认状态、收藏、笔记、计划和设置应与迁移前一致。
- 当迁移中任一步失败时，系统应回滚数据库事务并保留原 LocalStorage 数据与备份。
- 迁移成功后，系统应标记迁移版本；后续启动不得重复导入或制造重复数据。
- 系统不得静默删除旧 LocalStorage；只有在 SQLite 数据验证通过后才能将其标记为已迁移，且恢复入口所需备份必须保留。

### R4：桌面核心行为

- 当用户关闭主窗口且启用“关闭到托盘”时，应用应隐藏到托盘而不是退出；只有托盘“退出”才结束进程。
- 当阅读弹窗自动出现时，系统应记录 `shown`，不得自动记录 `confirmed`。
- 当悬浮入口或阅读弹窗显示时，系统应尽可能不改变当前前台应用焦点；验收应使用真实 Windows 输入窗口进行观察并记录结果。
- 当用户关闭弹窗、稍后提醒或今天暂停时，相应状态应正确持久化到 SQLite。
- 当电脑睡眠恢复或应用错过提醒时，系统不得补弹历史提醒。

### R5：构建、安装与启动

- 在前端门禁通过后，当执行 `cargo check --manifest-path src-tauri/Cargo.toml` 时，Rust/Tauri 工程应成功编译。
- 当执行 `npm run tauri:build` 时，系统应生成至少一个适用于当前 Windows 架构的本地安装包。
- 安装包应使用当前用户范围安装，不要求管理员权限；如系统组件安装确实需要提升权限，应明确提示而不是绕过。
- 安装完成后，应能从安装路径或开始菜单启动“弹阅”，显示主窗口并创建 SQLite 数据库。
- 应记录安装包路径、安装结果和已安装应用版本；不得声称已完成代码签名。

### R6：测试与交付状态

- `npm run verify` 应继续通过，现有 16 项文本导入和状态语义测试不得回归。
- 新增测试应覆盖 SQLite schema 版本、序列化往返、LocalStorage 迁移幂等、失败回滚以及浏览器回退。
- Rust 层新增数据库或窗口行为应至少通过 `cargo fmt --check` 和 `cargo check`。
- 完成后应更新 `PROJECT_STATUS.md`，区分自动化验证、人工真机验证和仍未完成的发布能力。

## 4. 数据与安全约束

- SQLite 数据库、迁移备份和日志不得包含 API Key；原文默认不上传网络。
- SQL 必须参数化，不拼接用户原文、书名或笔记。
- 迁移和批量保存必须使用事务。
- 数据库位于 Tauri 应用数据目录，不写入安装目录。
- 不执行 EPUB、网页或导入文本中的脚本。
- 安装过程只使用 Rust、Microsoft/Tauri 官方或项目已声明依赖的可信来源。

## 5. 本轮不改范围

- 不实现 EPUB、PDF、DOCX 或正式 Readability 网页适配器。
- 不实现 OCR、AI Provider、全屏/DND/会议检测。
- 不实现商业代码签名、自动升级、崩溃上报或应用商店发布。
- 不重做现有视觉设计和导航结构。
- 不删除用户原有 LocalStorage 数据或其他个人文件。
- 不宣称完成 macOS 或其他 Windows 机器的兼容性验证。
