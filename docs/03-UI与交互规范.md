# UI 与交互规范

## 1. 设计原则

### 1.1 像阅读产品，不像系统广告

- 暖纸张背景。
- 深灰而不是纯黑。
- 轻阴影、克制圆角。
- 中文正文优先阅读性。
- 不用大面积高饱和渐变。
- 不出现营销式红点和倒计时恐吓。

### 1.2 安静但可发现

提醒卡片出现时能够被看到，但不：

- 抢键盘焦点。
- 强制置于屏幕中央。
- 播放声音。
- 遮挡整个工作区。
- 强迫用户点击确认。

### 1.3 原文优先

阅读卡片视觉层级：

1. 书籍和章节。
2. 辅助短标题。
3. 原文。
4. 可展开的一句话理解。
5. 操作与倒计时。

解释默认弱于原文，不得使用同样的正文样式混在一起。

## 2. 视觉系统

### 2.1 色彩

```text
窗口背景：暖白与浅灰，避免大面积刺眼纯白
主表面：带轻微透明度的米白玻璃层
侧栏：浅色独立栏，用留白和细边界分区
主强调：克制的陶土橙
辅助色：鼠尾草绿、低饱和蓝，只用于书籍与状态
文字：暖深灰；次级文字使用中性灰
```

基础变量在 `src/styles.css` 中定义，v0.2 极简苹果风覆盖层位于 `src/apple.css`。不得直接复制 Apple 商标、专有图标或私有字体文件。

### 2.2 字体

- UI：系统无衬线字体。
- 阅读原文：系统宋体风格优先。
- 用户可以切换无衬线阅读。
- 不在交付包中捆绑第三方字体文件。

### 2.3 尺寸

桌面阅读卡片推荐：

- 宽 460～520 px。
- 高度随内容变化，上限约 700 px。
- 正文 17～20 px。
- 行高 1.8～2.0。
- 卡片边距 24～30 px。

## 3. 页面规范

### 今天

必须让用户在 5 秒内知道：

- 今天计划几段。
- 已展示和已确认多少。
- 正在读什么。
- 下一段是什么。
- 下一次什么时候出现。
- 如何立即读或暂停。

不要首先展示复杂图表。

### 书架

卡片显示：

- 封面占位。
- 类型和格式。
- 标题、作者。
- 确认进度。
- 片段数和字数。
- 继续阅读。

“添加新来源”始终可见。

### 阅读计划

不要用 Cron 表达。用户只配置：

- 哪些天。
- 每天几段。
- 哪些时间范围。
- 每段多长。
- 卡片按内容自适应或固定停留多久。
- 哪些时间属于安静时段。

右侧提供未来槽位预览，让设置结果可理解。

### 收藏与笔记

必须保留：

- 完整原文。
- 来源位置。
- 用户笔记。
- 回到连续阅读的入口。

### 设置

按“桌面行为、阅读外观、本地数据”分组，不展示尚未真正生效的系统检测或 AI Provider 开关。阅读外观提供自适应、紧凑、小窗三个弹窗占屏上限；它只约束最大尺寸，不改变切片和正文。

## 3.1 三窗口模型与悬浮图标

桌面版包含三个彼此分工明确的窗口：

- `main`：书架、计划、设置和连续阅读。
- `reading-floating`：52px 的透明悬浮入口。
- `reading-popup`：短时出现的独立微读卡片。

悬浮图标必须：

- 默认位于屏幕右侧，不遮挡任务栏。
- 只显示品牌入口，不使用意义不清晰的进度环和数字角标。
- 主窗口显示时隐藏，主窗口收起到托盘后恢复，避免遮挡应用自身操作。
- 点击后打开阅读弹窗；弹窗与入口保持相邻，设置关闭时不得残留。
- 浏览器预览支持拖动并记忆位置；原生多显示器位置需真机验收。

## 4. 弹窗生命周期

```text
创建/显示
→ 记录 shown
→ 倒计时开始
→ 鼠标悬停则暂停
→ 用户操作或倒计时结束
→ 隐藏
```

### 自动关闭

- 不记录 confirmed。
- 不自动跳到下一段。
- 下次仍可依据策略再次展示或继续序列。
- 默认使用预计阅读时长加轻量缓冲，短片段允许低于 30 秒。
- 用户可切换为 15～90 秒固定停留。
- 弹窗尺寸默认随正文自适应；紧凑档上限 520×560，小窗档上限 480×460，超出时只滚动正文区。

### 读完，下一段

- 当前标记 confirmed。
- 选择同一来源下一段。
- 下一段标记 shown。
- 卡片原地更新，不闪烁关闭再打开。

### 30 分钟后

- 写入 `snoozeUntil`。
- 记录 snoozed 事件。
- 立即隐藏。

### 今天暂停

- 写入次日零点的 `pausedUntil`。
- 首页、顶栏和计划页显示恢复时间并提供立即恢复。
- 立即隐藏弹窗，不确认当前片段。

### 展开连续阅读

- 当前可标记确认或由产品策略明确决定。
- 显示主窗口。
- 打开当前片段上下文。
- 隐藏弹窗。

## 5. 焦点规则

### 自动出现

- `focused(false)`。
- 不调用 `set_focus()`。
- 不发送全局键盘事件。
- 不将光标自动放入任何输入框。

### 用户点击

点击卡片后允许窗口获得交互焦点，保证按钮可用。

### 真机验收

必须在 Word、Excel、VS Code、浏览器输入框中持续打字，同时触发弹窗，确认：

- 字符仍进入原应用。
- 原应用不失去当前选区。
- 弹窗可见。
- 用户点击弹窗后按钮可操作。

## 6. 动画

- 页面进入 200～300 ms。
- 弹窗进入 180～220 ms。
- 侧栏滑入 200～240 ms。
- 不使用弹跳和连续闪烁。
- 用户开启“减少动画”后接近瞬时。

## 7. 响应式

虽然目标是电脑端，仍应覆盖：

- 1366×768。
- 1920×1080。
- 2K/4K 高 DPI。
- 100%～150% Windows 缩放。
- 窄窗口调试。

移动响应式只是保证可预览，不代表首版移动产品。

## 8. 文案原则

推荐：

- “读完，下一段”而不是“完成任务”。
- “今天不再提醒”而不是“放弃今天”。
- “已展示”而不是“已阅读”。
- “一句话理解”而不是“权威解读”。
- “阅读来源”而不是“数据库记录”。

避免：

- “你又没读”。
- “连续打卡即将中断”。
- “还剩 X 项任务”。
- “AI 已替你读完”。

## 9. 无障碍

- 所有图标按钮有 `aria-label`。
- 键盘可以关闭弹层。
- 颜色不是唯一状态标识。
- 文本对比度达到常规阅读要求。
- 焦点可见样式在正式版补齐。
- 屏幕阅读器应读出书名、章节、预计时长、原文和按钮。
