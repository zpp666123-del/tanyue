# 开发路线与验收

## 阶段 0：当前样板

已实现：

- 完整 UI。
- 浏览器可交互弹窗。
- TXT/MD/JSON 导入。
- 规则拆分。
- 阅读计划。
- 本地进度、收藏、笔记和导出。
- Tauri v2 源码底座。

验收命令：

```bash
npm run verify
```

## 阶段 1：Windows 桌面硬化

### Goal

在 Windows 10/11 真机完成 Tauri 编译和桌面行为闭环。

### 任务

- 安装 Rust 和 Tauri prerequisites。
- `cargo check`。
- 修正 API 或权限变化。
- 主窗口关闭到托盘。
- 托盘立即阅读、暂停 30 分钟、今天暂停、退出。
- 开机启动启停。
- 独立弹窗右下角展示。
- 弹窗不抢焦点。
- 多显示器和缩放。
- 休眠恢复不补弹。

### 门禁

没有通过“不抢焦点”测试，不进入解析器开发。

## 阶段 2：SQLite 与数据谱系

### Goal

把 LocalStorage 演示状态迁移为正式本地数据库。

### 任务

- schema 与迁移框架。
- repositories。
- 导入原文件缓存。
- 原文、block、segment run 和事件分表。
- LocalStorage 一次性迁移。
- 备份、恢复和删除。

### 门禁

- 迁移前后进度、收藏、笔记一致。
- 异常中断不损坏数据库。
- 删除来源可选择保留/删除笔记导出。

## 阶段 3：统一 SourceAdapter

### Goal

建立所有格式共用的标准化文档模型。

### 任务

- `NormalizedDocument`。
- `DocumentBlock`。
- 解析器版本。
- 来源锚点。
- 覆盖率报告。
- 导入预览与确认。

## 阶段 4：格式适配器

按顺序：

1. TXT/Markdown 正式化。
2. EPUB/foliate-js。
3. PDF.js 文字型 PDF。
4. Mammoth.js DOCX。
5. Readability 网页。

每个适配器都要有：

- 正常样本。
- 空文件。
- 超大文件。
- 加密或不可解析样本。
- 恶意内容样本。
- 锚点重开测试。

## 阶段 5：拆分器 2.0

### Goal

不仅“能切”，而且可证明没漏、没重、没乱序。

### 指标

- Block 覆盖率 100%。
- 重复引用 0。
- 句中硬切率低于既定阈值。
- 目标秒数 P50/P90 可控。
- 经典、非虚构、小说和技术文档策略可配置。

### AI

先只启用边界建议和辅助文案，必须有 schema 校验和规则回退。

## 阶段 6：智能暂停

- 全屏检测。
- Windows Focus Assist / DND。
- 锁屏。
- 休眠与唤醒。
- 空闲时间。
- 会议日历可选接入。

所有判断都应给出“为什么本次没弹”的可诊断记录。

## 阶段 7：发布工程

- Windows code signing。
- NSIS/WiX 安装器验收。
- 自动升级。
- 崩溃日志和用户授权。
- 数据目录说明。
- 卸载是否删除用户内容的选择。
- 隐私政策和第三方许可。

## 发布验收矩阵

### 内容

- 《道德经》81 章无缺失、重复和乱序。
- 20 万字现代书导入覆盖率 100%。
- EPUB CFI 可重开。
- PDF 页码可重开。
- DOCX 结构层级合理。

### 桌面

- Word 持续打字时弹窗不抢焦点。
- 多屏弹窗位置正确。
- 125%/150% 缩放不溢出。
- 主窗口关闭到托盘。
- 退出彻底结束。
- 开机启动可逆。
- 睡眠恢复不补弹。

### 数据

- 重启接续。
- 升级迁移。
- 数据导出。
- 删除与恢复。
- 笔记和收藏不因重新拆分丢失。

### 安全

- 不执行 EPUB/HTML 脚本。
- 不访问危险 URL 协议。
- 不内置 API Key。
- 日志不写入全文。
- Tauri capabilities 最小化。

### UX

- 关闭入口明显。
- 延后入口明显。
- 自动关闭不标记为读完。
- 自适应停留和 15/30/45/60/75/90 秒固定值均可用。
- 鼠标悬停或键盘焦点进入弹窗时暂停。
- 减少动画。
