# 架构与数据模型

## 1. 总体架构

```text
┌───────────────────────────────────────────┐
│ Tauri Desktop Shell                       │
│ Window / Tray / Autostart / Notification  │
├───────────────────────────────────────────┤
│ UI                                        │
│ Today / Library / Plan / Favorites /      │
│ Settings / Reading Popup / Reader Panel   │
├───────────────────────────────────────────┤
│ Application Services                      │
│ Import / Progress / Popup / Export        │
├───────────────────────────────────────────┤
│ Domain                                    │
│ NormalizedDocument / Segment / Scheduler  │
├───────────────────────────────────────────┤
│ Adapters                                  │
│ TXT / MD / EPUB / PDF / DOCX / URL / AI   │
├───────────────────────────────────────────┤
│ Persistence                               │
│ SQLite + file/object cache                │
└───────────────────────────────────────────┘
```

当前样板使用 LocalStorage，目的是让 UI 与业务纵向链路立即可运行。正式桌面版必须迁移 SQLite。

## 2. 领域对象

### Book

代表用户导入的一个阅读来源，不等同于磁盘文件。

关键字段：

- `id`
- `title`
- `author`
- `kind`
- `format`
- `sourceName`
- `sourceUrl`
- `segmentCount`
- `totalChars`
- `currentSequence`
- `createdAt`
- `updatedAt`
- `archived`

### Segment

产品的核心单位。

- `id`
- `bookId`
- `sequence`
- `chapterTitle`
- `helperTitle`
- `originalText`
- `contextBridge`
- `explanation`
- `estimatedSeconds`
- `sourceAnchor`
- `contentHash`
- `status`
- `favorite`
- `note`
- `viewCount`
- `lastShownAt`
- `confirmedAt`

### SourceAnchor

当前样板支持：

- `chapter`
- `line`
- `page`
- `cfi`
- `url`

正式版可扩展为结构化 JSON：

```json
{
  "type": "pdf_text_range",
  "page": 12,
  "start": 103,
  "end": 264,
  "quoteHash": "sha256:..."
}
```

### ReadingSchedule

- 是否启用。
- 一周哪几天。
- 每日数量。
- 弹窗停留时长。
- 目标阅读时长。
- 多个时间窗口。
- 安静时段。
- 延后截止。
- 暂停截止。
- 下一次到期时间。

### ActivityEvent

事件追加记录：

- `shown`
- `confirmed`
- `snoozed`
- `favorite`
- `imported`

后续可以派生统计，而不是在每个页面散落计数逻辑。

## 3. 标准化文档模型

建议正式版引入：

```ts
interface NormalizedDocument {
  sourceId: string;
  metadata: DocumentMetadata;
  blocks: DocumentBlock[];
  toc: TocNode[];
  parser: {
    name: string;
    version: string;
  };
}
```

`DocumentBlock`：

```ts
interface DocumentBlock {
  id: string;
  type: "heading" | "paragraph" | "list" | "quote" | "code" | "caption";
  text: string;
  level?: number;
  parentId?: string;
  anchor: SourceAnchor;
  hash: string;
}
```

任何解析器都先输出这个模型，拆分器不直接依赖 EPUB、PDF 或 DOCX 库。

## 4. SourceAdapter

```ts
interface SourceAdapter<Input> {
  id: string;
  version: string;
  detect(input: Input): Promise<number>;
  parse(input: Input, context: ParseContext): Promise<NormalizedDocument>;
  openAnchor(anchor: SourceAnchor): Promise<void>;
  dispose(): Promise<void>;
}
```

### 适配器建议

| 格式 | 适配器 | 锚点 |
|---|---|---|
| TXT/MD | 自研 | 行号 + 文本指纹 |
| EPUB/MOBI/AZW3 | foliate-js | CFI / section index |
| PDF | PDF.js | 页码 + 文本范围 |
| DOCX | Mammoth.js | XML/段落索引 + 指纹 |
| URL | HTTP + Readability | URL + DOM 路径 + 引文指纹 |

## 5. 拆分器

### 输入

- 标准化 blocks。
- 目标阅读秒数。
- 内容类型策略。
- 可选 AI 边界建议。

### 输出

- 候选片段。
- 覆盖率报告。
- 重复报告。
- 过短/过长报告。
- 来源锚点校验。

### 覆盖率

```text
covered_block_count / readable_block_count = 100%
```

必须同时保证：

```text
每个 readable block 的引用次数 = 1
```

### 版本化

正式版需增加：

```text
parser_version
segmenter_version
rule_version
ai_prompt_version
ai_model
created_at
```

重新拆分不得无声覆盖用户已有收藏和笔记，应做锚点迁移或生成新版本。

## 6. 阅读状态机

```text
unread
  │ popup shown
  ▼
shown
  │ explicit confirm
  ▼
confirmed
```

收藏和笔记与阅读状态正交。

自动关闭：

```text
unread → shown
shown  → shown
confirmed → confirmed
```

主动“读完，下一段”：

```text
current → confirmed
next    → shown
```

## 7. 调度状态机

### 需要持久化

- `schedule_id`
- `next_due_at`
- `last_triggered_slot`
- `snooze_until`
- `paused_until`
- `date_key`
- `shown_today`

### 启动恢复

```text
应用启动
→ 读取计划
→ 判断日期是否变化
→ 清理过期 snooze/pause
→ 根据当前时间重新计算下一槽位
→ 不补弹已错过槽位
```

### 休眠恢复

```text
resume event
→ 设置短缓冲期
→ 重新计算未来槽位
→ 丢弃过去槽位
→ 检查全屏/DND/会议
```

## 8. 正式 SQLite 建议

```sql
books
sources
source_versions
blocks
segment_runs
segments
segment_block_links
reading_events
favorites
notes
schedules
settings
ai_cache
migrations
```

关键关系：

```text
Source → SourceVersion → Block
SourceVersion + RuleVersion → SegmentRun → Segment
Segment ↔ Block through segment_block_links
```

这使得“原始内容、解析版本、拆分版本、AI 辅助版本”彼此可追溯。

## 9. 文件存储

原始导入文件不要塞入 SQLite 大字段。建议：

```text
app-data/
  sources/<source-id>/original.ext
  sources/<source-id>/normalized.json.zst
  cache/covers/
  cache/ai/
  backups/
```

每个原始文件记录 SHA-256、大小、MIME、导入时间和原文件名。

## 10. Tauri 窗口

### main

- 常规主窗口。
- 关闭时隐藏到托盘。
- 托盘“退出”才真正结束进程。

### reading-popup

- 无边框。
- 始终置顶。
- 跳过任务栏。
- 初始不聚焦，但允许用户点击交互。
- 默认右下角并避免溢出工作区。
- 关闭时隐藏，减少频繁创建成本。

## 11. AI Provider

```ts
interface AiProvider {
  suggestBoundaries(input: NumberedBlocks): Promise<BoundarySuggestion>;
  enrichSegments(input: ImmutableOriginalSegments): Promise<SegmentEnrichment[]>;
}
```

严格校验：

- 返回的 block id 必须都存在。
- 不得重复或漏掉 block。
- 原文从本地 block 重新拼接，而不是信任模型回传文本。
- JSON Schema 校验失败则回退规则拆分。

## 12. 可观测性

本地软件仍需要：

- 导入阶段日志。
- 解析器耗时。
- 覆盖率。
- 弹窗触发原因和跳过原因。
- SQLite 迁移状态。
- 崩溃报告需用户同意且脱敏。

禁止记录完整敏感文档正文到普通日志。
